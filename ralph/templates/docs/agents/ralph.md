# Ralph

Ralph is the execution-only Agent Queue runner for this repository.

## Runtime

- Repository: `{{REPO}}`
- Default branch: `{{DEFAULT_BRANCH}}`
- GitHub Project configured: `{{PROJECT_CONFIGURED}}`
- GitHub Project owner: `{{PROJECT_OWNER}}`
- GitHub Project number: `{{PROJECT_NUMBER}}`
- Branch prefix: `agent/issue-`

## Execution Contract

Ralph consumes only issues that have already been triaged to the canonical `ready-for-agent` role.

Ralph must not run `/to-prd`, `/to-issues`, or `/triage` automatically. Planning and triage remain maintainer-triggered.

Fresh work must satisfy all of these rules:

- The issue is open in this repository.
- The issue has exactly one category role.
- The issue has exactly one triage-state role, and it is `ready-for-agent`.
- The issue has no open linked PR.
- The issue is not blocked by unresolved dependencies, missing product decisions, missing external access, or missing human input.
- If a GitHub Project is configured, the issue is in the Project with `Status: Todo`.

## Handoff

When implementation is complete, Ralph should open or update a PR and include `Closes #<issue-number>` in the PR body.

Ralph must keep the issue open until merge or explicit human action. If a GitHub Project is configured, Ralph must keep Project `Status: In Progress` at PR handoff.

## Not Actually Ready

If Ralph discovers that a `ready-for-agent` issue is not actually AFK-ready, it may demote the issue to `needs-info` or `ready-for-human`, comment with the missing information, reset Project `Status: Todo` when configured, unassign itself, and continue to the next eligible issue.

Triage-like comments must start with:

```markdown
> *This was generated by AI during triage.*
```

## Local Entrypoints

Local Ralph entrypoints are machine-specific symlinks and should not be committed. The onboarding script adds them to `.git/info/exclude`.
